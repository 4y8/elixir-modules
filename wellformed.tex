\section{Definitions}

We propose the following addition to the module language syntax:

\begin{figure}[h]
    \begin{center}
        \begin{tabular}{r c ll}
            $P$         & ::= & $\Elixir$                          & \color{gray} root                                      \\
                        & |   & $\Elixir.\rho$                     & \color{gray} subpath                                   \\[3mm]
            $\rho$      & ::= & $X$                                                                                         \\
                        & |   & $X.\rho$                                                                                    \\[3mm]
            $\Pi$       & ::= & $\epsilon$                                                                                  \\
                        & |   & $P$                                                                                         \\[3mm]
            $\pi$       & ::= & $\epsilon$                                                                                  \\
                        & |   & $\rho$                                                                                      \\[3mm]
            $M$         & ::= & $X$                                                                                         \\
                        & ::= & $\Elixir.\rho[\overline{\tx = t}]$                                                          \\[3mm]
            $\Next$     & ::= & $N$                                                                                         \\
                        & |   & $\tx$                                                                                       \\[3mm]
            $\Gammatop$ & ::= & $\overline{X : \Moddecl}$          & \color{Gray} global environment                        \\[3mm]
            $\Gammabot$ & ::= & $\overline{D}$                     & \color{Gray} local environment ($D \neq X : \Moddecl$)
        \end{tabular}
    \end{center}
    \caption{Some addition to the module language syntax}
\end{figure}

$\Gammatop$ is the global environment. It contains top-level \texttt{defmodule} declarations.

$\Gammabot$ is the local environment. It cannot contain \texttt{defmodule} declarations.

Empty environments will be denoted $\emptyenv$. \\

By abuse of notation, $X.\epsilon$ and $X$ will denote the same thing.
This will allow us to write $X.\pi$ where $\pi$ is a possibly empty path. \\

We consider behavior environments and declaration lists as partial functions
from $\BX$ and $\Next$ to $\Beh$ and $D$, respectively.
If the name appears multiple time in the list, the right-most occurrence is returned, as one would expect.

We extend the notation to paths:

\begin{center}
    \begin{tabular}{rll}
        $(\overline{D})(X.\rho)$          & $=$ & $(\overline{D})(X)(\rho)$ \\
        $\left(X : \Moddecl\right)(\rho)$ & $=$ & $(\overline{D})(\rho)$
    \end{tabular}
\end{center}

\section{Wellformedness}

We introduce wellformedness judgements:

\begin{figure}[H]
    \begin{center}
        \begin{tabular}{lrll}
            Behavior environments: &                                     & $\vdash \Sigma$                      \\[2mm]
            Global environments:   & $\Sigma$                            & $\vdash \Gammatop$                   \\[2mm]
            Local environments:    & $\Pi; \Sigma; \Gammatop$            & $\vdash \Gammabot$    & \color{Gray} \\[2mm]
            Declaration lists:     & $\Pi; \Sigma; \Gammatop; \Gammabot$ & $\vdash \overline{D}$ & \color{Gray} \\[2mm]
            Type:                  & $\Pi; \Sigma; \Gammatop; \Gammabot$ & $\vdash T$
        \end{tabular}
    \end{center}
\end{figure}

$\Pi$ will be $\epsilon$ when type-checking behaviors; it will be $\Elixir$ when checking top-level modules, and $\Elixir.\rho$ otherwise.

\subsection{Behavior environments}

\[
    \begin{prooftree}
        \infer0{ \vdash \emptyenv }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \vdash \Sigma }
        \hypo{ \epsilon; \Sigma; \emptyenv; \overline{\tx : \star} \vdash \overline D }
        \infer2{ \vdash \Sigma, \BX : \Lambda (\overline{\tx : \star}).\{\overline{D}\} }
    \end{prooftree}
\]

This rule also requires the $\overline{\tx}$ are pairwise distinct.

Because we use $\epsilon$ as the path in the rule above, the behavior will not be
able to declare submodules (see the section about wellformedness of declaration lists). This is intended.

\subsection{Global environments}
\[
    \begin{prooftree}
        \hypo { \vdash \Sigma }
        \infer1 { \Sigma \vdash \emptyenv }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{\Sigma \vdash \Gammatop}
        \hypo{ \Elixir; \Sigma; \Gammatop; \emptyenv \vdash X : \Moddecl }
        \infer2{ \Sigma \vdash \Gammatop, X : \Moddecl }
    \end{prooftree}
\]

In the rule above, $ \Elixir; \Sigma; \Gammatop; \emptyenv \vdash X : \Moddecl$
refers to the wellformedness of declaration lists.

\subsection{Local type environments}

Recall the shape of the judgement: $\Pi; \Sigma; \Gammatop \vdash \Gammabot$.

\[
    \begin{prooftree}
        \hypo{ \Sigma \vdash \Gammatop}
        \infer1{ \Pi; \Sigma; \Gammatop \vdash \emptyenv }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash t }
        \hypo{ \Pi \neq \Elixir }
        \infer2{ \Pi; \Sigma; \Gammatop \vdash \Gammabot, X : t }
    \end{prooftree}
\]
\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop \vdash \Gammabot }
        \hypo{ \Pi \neq \Elixir }
        \infer2{ \Pi; \Sigma; \Gammatop \vdash \Gammabot, \tx : \star }
    \end{prooftree}
\]
\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash t }
        \hypo{ \Pi \neq \Elixir }
        \infer2{ \Pi; \Sigma; \Gammatop \vdash \Gammabot, \tx : [= t] }
    \end{prooftree}
\]
\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop \vdash \Gammabot }
        \hypo{ \overline{\Pi; \Sigma; \Gammatop; \Gammabot \vdash T} }
        \hypo{ \Pi \neq \Elixir }
        \infer3{ \Pi; \Sigma; \Gammatop \vdash \Gammabot, x : \bigcap \overline{T} }
    \end{prooftree}
\] \\

Note that we have no rule to add $X : \Moddecl$ to $\Gammabot$. Therefore, for what concerns module declarations, a local type environment $\Gammabot$ cannot contain module declaration but only type assumptions for module parameters.
Also, only the empty environment is wellformed in path $\Elixir$.


\subsection{Declaration list}

We define the function $\name(D)$ as $\name: \left\{\begin{array}{ll}
        X : \Moddecl             & \mapsto X   \\
        X : t                    & \mapsto X   \\
        x : \bigcap \overline{T} & \mapsto x   \\
        \tx : \star              & \mapsto \tx \\
        \tx : [=t]               & \mapsto \tx
    \end{array}\right.$  \\[3mm]

We also define the notation $\left(\overline{D}\right)[\pi \texttt{+=} D']$ as:

\begin{figure}[H]
    \begin{tabular}{lll}
        $\left(\overline{D}\right)[\epsilon \texttt{+=} D']$                                 & = $\overline{D}, D$                                                                          \\[3mm]
        $\left(\overline{D}, X : \Moddecl[\tx][\overline{D'}]\right)[X.\pi \texttt{+=} D'']$ & = $\overline{D}, X : \Moddecl[\tx][\left(\overline{D'}\right)[\pi \texttt{+=} D'']]$         \\[3mm]
        $\left(\overline{D}, D'\right)[X.\pi \texttt{+=} D'']$                               & $= \left(\overline{D}\right)[X.\pi \texttt{+=} D''], D'$ \hspace*{15mm}if $\name(D') \neq X$ \\[3mm]
        undefined otherwise
    \end{tabular}
    \caption{Notation $\left(\overline{D}\right)[\pi \texttt{+=} D']$}
\end{figure}

We also define the extension: $\left(\overline{D}\right)[\Elixir.\pi \texttt{+=} D'] = \left(\overline{D}\right)[\pi \texttt{+=} D']$.

Note that we may only add a declaration to a $X: \Moddecl$, and this module must already be present in the declaration list.

The above notations and definitions allow us to propose the following rules for well-formedness of type environments.
\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash \emptyenv }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ P; \Sigma; \Gammatop[P \texttt{+=} D]; (\Gammabot, D) \vdash \overline{D'} }
        \hypo{ \name(D) \notin \dom(\Gammabot) }
        \infer2{ P; \Sigma; \Gammatop; \Gammabot \vdash D, \overline{D'} }
    \end{prooftree}
\]

The following rule is only used inside behaviors:

\[
    \begin{prooftree}
        \hypo{ \epsilon; \Sigma; \emptyenv; (\Gammabot, D) \vdash \overline{D'} }
        \hypo{ \name(D) \notin \dom(\Gammabot) }
        \infer2{ \epsilon; \Sigma; \emptyenv; \Gammabot \vdash D, \overline{D'} }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ P.X; \Sigma; \Gammatop\left[P \texttt{+=} X : \Lambda (\overline{\tx : \star}). \{ \}\right]; \overline{\tx : \star} \vdash \{ \overline{D} \}_{\overline{\BX[\overline{\tx' = t}]}}}
        \hypo{ P; \Sigma; \Gammatop\left[P \texttt{+=} X : \Moddecl\right]; \Gammabot \vdash \overline{D'}}
        \infer2{ P; \Sigma; \Gammatop; \Gammabot \vdash \left(X : \Moddecl\right), \overline{D'} }
    \end{prooftree}
\]
The above rule also requires the $\overline{\tx} \text{ are pairwise distinct}$

Note that we only add $\Lambda (\overline{\tx : \star}). \{ \}$ to the global environment
when we check the submodule. As a result, a declaration in the submodule cannot
refer to later declarations, even when using the absolute qualified path.

This is a limitation of the current approach: we cannot add $\overline{D}$ to the global environment
before we check that $\overline{D}$ is wellformed.

\subsection{Pretypes}

\[
    \begin{prooftree}
        \hypo { \Pi; \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash \tau }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \overline{\Pi; \Sigma; \Gammatop; \Gammabot \vdash t}}
        \hypo{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash t'}
        \infer2{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash (\overline{t}) \rightarrow t' }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop \vdash \Gammabot }
        \hypo{ \overline{\Pi; \Sigma; \Gammatop; \Gammabot \vdash t} }
        \infer2{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash  \%\{ \overline{k: t} \} }
    \end{prooftree}
\]

Keys $\overline{k}$ also need to be pairwise distinct. \\

\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash t }
        \hypo{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash t' }
        \infer2{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash  t \vee  t' }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash t }
        \infer1{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash  \lnot t }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop \vdash \Gammabot }
        \hypo{ \tx \in \dom(\Gammabot) }
        \infer2{ \Pi;  \Sigma; \Gammatop; \Gammabot \vdash \tx }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \Pi; \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { \Sigma(\BX) = \BX : \Lambda \left( \overline{\tx : \star} \right) \{\overline D \}}
        \hypo { \overline {\Pi; \Sigma; \Gammatop; \Gammabot \vdash t} }
        \infer3{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash \BX [\overline{\tx = t}]  }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash M : \{ \tx : \star \} }
        \infer1{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash M.\tx }
    \end{prooftree}
\]

In the above rule, $\Pi; \Sigma; \Gammatop; \Gammabot \vdash M : \{ \tx : \star \}$ is a typing judgement.
Thanks to subtyping, $\{ \tx : \star \}$ may not be exactly the type associated with $M$ in $\Gammatop$ or $\Gammabot$.


\subsection{Singleton module type}

\[
    \begin{prooftree}
        \hypo { P; \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { \Gammatop(\rho) = X : \Moddecl[\tx] [\overline{D}][\BX][\tx'][t']}
        \hypo { \overline{P; \Sigma; \Gammatop; \Gammabot \vdash t} }
        \infer3{ P; \Sigma; \Gammatop; \Gammabot \vdash \langle \Elixir.\rho[\overline{\tx = t}] \rangle }
    \end{prooftree}
\]

where $X$ is the last component of $\rho$. Note that this rule cannot be applied to the empty
path, because it's not possible to refer to $\Elixir$ while we are checking behaviors.

\[
    \begin{prooftree}
        \hypo {\Gammabot(X) = X : t }
        \hypo { \Pi; \Sigma; \Gammatop; \Gammabot \vdash t \preceq \mod }
        \infer2{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash \langle X \rangle }
    \end{prooftree}
\]

In the rule above, $X$ is a local variable (in practice, a function parameter).
As a result, it must have an already instantiated type (parametric modules are not types).
That's why we don't allow instantiating $X$ again.

\section{Subtyping}

Elixir's semantic subtyping will be denoted $ t \vartriangleleft t'$.

We denote $\Omega$ the type of a declaration (i.e, the part on the right of the semicolon).
All declarations can be written as $D = N : \Omega$ (but not all $N : \Omega$ are valid declarations).


We define the syntactic subtyping judgement: $\Sigma; \Gammatop; \Gammabot \vdash \Omega \preceq \Omega'$.
We will denote $\Omega \simeq \Omega'$ when both $\Omega \preceq \Omega'$ and $\Omega' \preceq \Omega$ hold.

\section{Expressions}

We define the expression typing judgement: $P; \Sigma; \Gammatop; \Gammabot \vdash E : T$.
