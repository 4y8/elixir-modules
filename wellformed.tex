\section{Outline}

We propose a new type system for Elixir's modules.
The syntax language is available in file \texttt{melixir.pdf} on page 10.
We recall most of it in this document.

We will rewrite it cleanly in this document later.

\paragraph{Elixir program}

We represent an Elixir program as a list of behaviours $\overline{\mathcal{B}}$ followed by a
list of bindings $\overline{B}$.

Behaviours are the Elixir equivalent of interfaces, traits, or signatures in other languages. In the specific case of Elixir, behaviours are nominal types for modules.
Bindings are type, function or module definitions. Module definitions are again lists of bindings;
The toplevel list of bindings $\overline{B}$ that forms the program  must be a list of module definitions.
This is formalized later in this document, in the inference rules for the wellformedness judgements.

Checking a program involves checking that all behaviours and bindings are well-formed.
Informally, a behaviour is well-formed if all type and behaviour names in it are \textit{bound},
that is, they are declared before use. A binding is wellformed if all type, behaviour and module
names are bound and the values it defines are well typed.

\paragraph{Scoping rules and non-recursiveness}

We impose a significant limitation compared to current Elixir's functionality.
Elixir allows mutually recursive module definitions, but the system we propose
currently does not. At any point of the program, only preceding behaviours
and declarations can be used. In particular, because we separate behaviours and bindings
in two lists and we process behaviours first, behaviours cannot refer to modules at all.

Supporting mutually recursive modules would add significant complexity and is kept as
a work for later.

\paragraph{Modules and submodules}

Recall module paths:

\begin{center}
    \begin{tabular}{rcll}
        $P$ & ::= & $X$ | $P.X$                           \\
        $M$ & ::= & $X$ | $\Elixir.P[\overline{\tx = t}]$
    \end{tabular}
\end{center}

$P$ is the absolute path of the module. $X$ ranges over module names.

$M$ is a module expression. It can either instantiate a module
from its absolute path, or refer to an already instantiated module stored
in local variable $X$ (typically, a function parameter).

Absolute paths are qualified with the $\Elixir$ prefix to remove ambiguity
between the local variable $X$ and the top-level module with name $X$.

By abuse of notation, we will omit the square brackets when
the instantiation is empty. That is, we will write $\Elixir.P$ instead
of $\Elixir.P[]$ \\

Note that submodules are not member of their enclosing module.
It is not possible to access submodules of the module stored in
local variable $X$. The module must be accessed using its absolute path instead.

Admittedly, Elixir does allow references to a submodule from within its enclosing
module using relative paths.
However, this is only syntactic sugar. Relative paths are expanded by the compiler to
their corresponding absolute path before they reach the type system.

\paragraph{Types}

For conciseness, we restrict Elixir's types to a small subset, to which
we add some types specific to the module system.

In some examples, we will also mention base types such as $\texttt{integer()}$ and $\texttt{boolean()}$,
but we do not include them in the formal type system. Extending the type system
to include those base types is straightforward and orthogonal to the module system.

We also define the abbrevations: $\toptype = \lnot \mathbb{O}$ and $t \wedge t' = \lnot(\lnot t \vee \lnot t')$.

\begin{center}
    \begin{tabular}{rcll}
        $t$          & ::= & $ ... $                                                   & \color{Gray}  core types and operators $\vee$, $\lnot$, see \texttt{melixir.pdf} \\
                     & |   & $\tx$                                                     & \color{Gray} local type or type parameter                                        \\
                     & |   & $M.\tx$                                                   & \color{Gray} type imported from module $M$                                       \\
                     & |   & $\BX[\overline{\tx = t}]$                                 & \color{Gray} type of a module that implements the behaviour $\BX$                \\
                     & |   & $\langle M \rangle$                                       & \color{Gray} singleton type of module $M$                                        \\[3mm]
        $T$          & ::= & $t$                                                                                                                                          \\
                     & |   & $(\overline{N : T}) \rightarrow T$                                                                                                           \\[3mm]
        $\mathbb{T}$ & ::= & $T$                                                                                                                                          \\
                     & |   & $\{ \overline{D} \}_{\overline{\BX[\overline{\tx = t}]}}$ & \color{gray} strucural module signature                                          \\
                     & |   & $\mathbb{T} \cap \mathbb{T}$                              & \color{gray} syntactic intersection
    \end{tabular}
\end{center}

Types $t$ are semantic types.
Types $T$ are types we do not know how to encode semantically. They are only manipulated syntactically.

The separation between $T$ and $\mathbb{T}$ does not appear in \texttt{melixir.pdf}, but it
just means that module signatures $\{ \overline{D} \}$ cannot appear in source programs.
Expanded module signatures only show up in derivation trees when we check wellformedness of $M.\tx$ and $M.x$,
but they never end up in environments.

This will save us from a lot of edge cases in capture-avoiding substitutions later.

\paragraph{Environments}

Recall the definition of behaviour, module and local environments:

\begin{center}
    \begin{tabular}{rl}
        $\Sigma ::=$    & $\overline{\mathcal B}$   \\[3mm]
        $\Gammatop ::=$ & $\overline{X : \Moddecl}$ \\[3mm]
        $\Gammabot ::=$ & $\overline{D}$
    \end{tabular}
\end{center}

where $\mathcal{B} ::= \BX : \Lambda (\overline{\tx : \star}) . \{ \overline{D} \}$
is a behaviour declaration, $D$ is a local declaration:

\begin{center}
    \begin{tabular}{rcll}
        $D$ & ::= & $ X : t$                   & \color{Gray} local variable with module or behaviour type     \\
            & |   & $x : \bigcap \overline{T}$ & \color{Gray} exports a value $x$ of type $\bigcap\overline T$ \\
            & |   & $\tx : \star$              & \color{Gray} exports an opaque type $\tx$                     \\
            & |   & $\tx : [=t]$               & \color{Gray} exports a transparent type alias $\tx = t$
    \end{tabular}
\end{center}

and $\mathcal{D}$ is either a local declaration or a submodule declaration:

\begin{center}
    \begin{tabular}{rcl}
        $\mathcal{D}$ & ::= & $D$            \\
                      & |   & $X : \Moddecl$
    \end{tabular}
\end{center}

Modules contain their submodules in the module environment $\Gammatop$
because the scoping rules described above require preserving the order
of the declarations. This does not invalidate the previous claim that
submodules are not exported by their enclosing module (hence the normal $D$
in module signatures $\{ \overline{D} \}$).
Similarly, declarations $X : t$ are reserved to local variables and, as such,
cannot appear in module signatures $\{ \overline{D} \}$ either.
In particular, they cannot be used to export a submodule. \\

Empty lists and empty environments are denoted $\emptyenv$. We consider behaviour, module and local
environments as partial functions over $\BX$, $\Next$ and $\Next$ respectively,
where $\Next ::= N$ | $\tx$ ranges over declaration names.

By extension, we consider global environments as partial functions over $P$:

$$
    (\overline{\mathcal{D}})(X.P) = (\overline{\mathcal{D}})(X)(P)
$$
$$
    \left(X : \Moddecl\right)(P) = (\overline{\mathcal{D}})(P)
$$

\paragraph{Judgments}

We define the following judgements:

\begin{figure}[H]
    \begin{center}
        \begin{tabular}{lrl}
            Wellformedness of behaviour environments: &                                     & $\vdash \Sigma$                                 \\[2mm]
            Wellformedness of module environments:    & $\Sigma$                            & $\vdash \Gammatop$                              \\[2mm]
            Wellformedness of local environments:     & $\Sigma; \Gammatop$                 & $\vdash \Gammabot$                              \\[2mm]
            Wellformedness of types:                  & $\Sigma; \Gammatop; \Gammabot$      & $\vdash \mathbb{T}$                             \\[2mm]
            Subtyping:                                & $\Sigma; \Gammatop; \Gammabot$      & $\vdash \mathbb{T} \preceq \mathbb{T}'$         \\[2mm]
            Expression typing:                        & $\Sigma; \Gammatop; \Gammabot$      & $\vdash E : \mathbb{T} $                        \\[2mm]
            Binding typing:                           & $\Pi; \Sigma; \Gammatop; \Gammabot$ & $\vdash \overline{B} : \overline{\mathcal{D}} $ \\[2mm]
        \end{tabular}
    \end{center}
\end{figure}
where $\Pi := \epsilon$ | $P$ (occurring in the binding typing judgement above) is a possibly empty path.

The wellformedness of module environments will also need a further auxiliary judgement, which will be defined in the corresponding section.

Let $\overline{\mathcal B}, \overline{B}$ be a program. The program passes type-checking if there exists a wellformed module environment $\Gammatop$ such that both
$$\vdash \overline{\mathcal B} \quad \text{ and } \quad \epsilon; \overline{\mathcal{B}}; \emptyenv; \emptyenv \vdash \overline{B} : \Gammatop$$ hold.

Note that we write $\overline{B} : \Gammatop$ because top-level bindings can only be module declarations.

\paragraph{Shadowing and alpha-renaming}

The type system strictly prohibits name shadowing.

This restriction is a direct consequence of representing
environments as partial functions that resolve to the right-most binding. Allowing shadowing would implicitly alter the meaning of any prior declarations that refer to the shadowed name.

While this correctly rejects modules that export the same name twice
and functions with duplicate parameter names,
it also brings some limitations that are worth mentioning.

Function parameters cannot shadow local module declarations.
We consider this limitation orthogonal to the type system and
it is the responsibility of the programmer to rename function parameters.

Another, more critical limitation, regards the wellformedness of
module signatures $\{ \overline{D} \}$. This limitation, and the workaround,
will be explained in more details in the corresponding section.


\section{Wellformedness}

In this section we give inference rules for the wellformedness judgements.

\subsection{Behaviour environments}

\[
    \begin{prooftree}
        \infer0{ \vdash \emptyenv }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \BX \notin \dom(\Sigma) }
        \hypo{ \Sigma; \emptyenv; \overline{\tx : \star} \vdash \{ \overline{D} \}}
        \infer2{ \vdash \Sigma, \BX : \Lambda (\overline{\tx : \star}).\{\overline{D}\} }
    \end{prooftree}
\]

$ \Sigma; \emptyenv; \overline{\tx : \star} \vdash \{ \overline{D} \}$ refers to the wellformedness of types.

\subsection{Module environments}

\[
    \begin{prooftree}
        \hypo { \vdash \Sigma }
        \infer1 { \Sigma \vdash \emptyenv }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \epsilon; \Sigma; \Gammatop; \emptyenv \vdash X : \Moddecl }
        \infer1{ \Sigma \vdash \Gammatop, X : \Moddecl }
    \end{prooftree}
\] \\

The hypothesis refers to the wellformedness of declaration lists: $$\Pi; \Sigma; \Gammatop; \Gammabot \vdash \overline{\mathcal{D}}$$
This judgement is not to be confused with the wellformedness of the type $\{\overline{D}\}$, which can only contain local declarations.

We give inference rules for the wellformedness of declaration lists below.
First, we need to introduce two new notations:
$\locals$ takes the list of declarations of a module and filters out submodule
declarations, so as to keep only local declarations. $(\overline{\mathcal{D}})[\Pi \texttt{+=} \mathcal{D}']$ adds a declaration
to a module in the module environment. The notations are formally defined below.

\begin{figure}[H]
    \begin{center}
        \begin{tabular}{rl}
            $\locals(\emptyenv)$                                        & $= \emptyenv$                          \\
            $\locals(D, \overline{\mathcal{D}})$                        & $= D, \locals(\overline{\mathcal{D}})$ \\
            $\locals\left(X : \Moddecl, \overline{\mathcal{D'}}\right)$ & $= \locals(\overline{\mathcal{D'}})$
        \end{tabular}
    \end{center}
    \caption{Meta-function $\locals(\overline{\mathcal{D}})$}
\end{figure}

\begin{figure}[H]
    \begin{center}
        \begin{tabular}{ll}$
            \left(\overline{\mathcal{D}}\right)\left[\epsilon \texttt{+=} \mathcal{D}'\right]$                               & = $\overline{\mathcal{D}}, \mathcal{D}'$                                                              \\
            $\left(\overline{\mathcal{D}}, X : \Moddecl[\tx][\overline{\mathcal{D}'}]\right)[X \texttt{+=} \mathcal{D}'']$   & = $\overline{\mathcal{D}}, X : \Moddecl[\tx][\overline{\mathcal{D}'}, \mathcal{D}'']$                 \\
            $\left(\overline{\mathcal{D}}, X : \Moddecl[\tx][\overline{\mathcal{D}'}]\right)[X.P \texttt{+=} \mathcal{D}'']$ & = $\overline{\mathcal{D}}, X : \Moddecl[\tx][(\overline{\mathcal{D}'})[P \texttt{+=} \mathcal{D}'']]$ \\
            undefined otherwise
        \end{tabular}
    \end{center}
    \caption{Notation $(\overline{\mathcal{D}})[\Pi \texttt{+=} \mathcal{D}']$}
\end{figure}

Note that this notation only allows adding a declaration to
the last module in the list. As a result, we do not need a
definition for $\left(\overline{\mathcal{D}}, Y : \Moddecl[\tx][\overline{\mathcal{D}'}]\right)[X \texttt{+=} \mathcal{D}'']$
when $X \neq Y$.

\paragraph{Local declarations}

Intuitively, a local declaration is wellformed if we can add it to the
local environment built so far.

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot, D }
        \infer1 { P; \Sigma; \Gammatop; \Gammabot \vdash D }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { P; \Sigma; \Gammatop[P \texttt{+=} D]; \Gammabot, D \vdash \overline{\mathcal{D}'} }
        \infer1[$\overline{\mathcal{D}'} \neq \emptyenv$] { P; \Sigma; \Gammatop; \Gammabot \vdash D, \overline{\mathcal{D}'} }
    \end{prooftree}
\]

Note that in the rules above, $P$ cannot be the empty path, because local declarations
can only appear inside a module. The special rule when there is a single local declaration is necessary to break
cycles in the definition.
Indeed, checking the wellformedness of the local environment will in turn
require checking the wellformedness of the module environment built so far.
We need this environment to be stricly smaller than the initial environment, otherwise we would get stuck.

\paragraph{Module declarations}

By abuse of notation, we consider that $\epsilon.X$ denotes $X$. This avoids duplicating the rules.

In order to avoid cyclic rules and to keep the rules legible, we break wellformedness of submodules into three steps:
\begin{itemize}
    \item In the first rule, we check that the module does not already exist
          in the environment and that its parameter names are pairwise distinct.
    \item In the second rule, we check that the submodule's declaration list is wellformed.
    \item In the third rule, we check that the submodule effectively implements the behaviours it declares.
\end{itemize}

Finally, the fourth rule checks the subsequent declarations after the current submodule.

Note that all the rules check the wellformedness of the local environment, which implies the
wellformedness of the module environment.
As a result, when a rule adds a declaration to the module environment in the premise,
it implicitly requires this declaration to be wellformed.

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { \Sigma; \Gammatop \vdash \overline{\tx : \star} }
        \hypo { \Pi.X \notin \dom(\Gammatop) }
        \infer3{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash X : \Lambda (\overline{\tx : \star}). \{\} }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { \Pi.X; \Sigma; \Gammatop[\Pi \texttt{+=} X : \Lambda(\overline{\tx : \star}). \{\}]; \overline{\tx : \star} \vdash \overline{\mathcal{D}}}
        \infer2[$\overline{\mathcal{D}} \neq \emptyenv$]{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash X : \Lambda (\overline{\tx : \star}). \{ \overline{\mathcal{D}} \} }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { \Sigma; \Gammatop\left[\Pi \texttt{+=} X : \Lambda (\overline{\tx : \star}). \left\{ \overline{\mathcal{D}}\right\}\right]; \overline{\tx : \star} \vdash \{ \locals( \overline{\mathcal{D}})\}_{\overline{\BX[\overline{\tx' = t}]}} }
        \infer2[$\overline{\BX} \neq \emptyenv$]{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash X : \Moddecl }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo { \Pi; \Sigma; \Gammatop\left[\Pi \texttt{+=} X : \Moddecl\right]; \Gammabot \vdash \overline{\mathcal{D}'} }
        \infer1 [$\overline{\mathcal{D}'} \neq \emptyenv$]{ \Pi; \Sigma; \Gammatop; \Gammabot \vdash X : \Moddecl, \overline{\mathcal{D}'} }
    \end{prooftree}
\]


\subsection{Local type environments}

\[
    \begin{prooftree}
        \hypo{ \Sigma \vdash \Gammatop}
        \infer1{ \Sigma; \Gammatop \vdash \emptyenv }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop \vdash \Gammabot }
        \hypo{ \tx \notin \dom(\Gammabot) }
        \infer2{ \Sigma; \Gammatop \vdash \Gammabot, \tx : \star }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t }
        \hypo{ \tx \notin \dom(\Gammabot) }
        \infer2{ \Sigma; \Gammatop \vdash \Gammabot, \tx : [= t] }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t \preceq \mod }
        \hypo{ X \notin \dom(\Gammabot) }
        \infer2{ \Sigma; \Gammatop \vdash \Gammabot, X : t }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \overline{\Pi; \Sigma; \Gammatop; \Gammabot \vdash T} }
        \hypo{ x \notin \dom(\Gammabot) }
        \infer2[$\overline{T} \neq \emptyenv$]{ \Pi; \Sigma; \Gammatop \vdash \Gammabot, x : \bigcap \overline{T} }
    \end{prooftree}
\] \\

Note that (if we defined inference rules properly),
$\Sigma; \Gammatop; \Gammabot \vdash t \preceq t'$ implies $\Sigma; \Gammatop; \Gammabot \vdash t$,
which in turn implies $\Sigma; \Gammatop \vdash \Gammabot$;
that is why we did not mention this as an explicit premise in the rules above.


\subsection{Pretypes}

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash k }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \atom }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \mod }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \fun }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \mathbb{O} }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \alpha }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ \overline{ \Sigma; \Gammatop; \Gammabot \vdash t}}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t'}
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{t}) \rightarrow t' }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop \vdash \Gammabot }
        \hypo{ \overline{ \Sigma; \Gammatop; \Gammabot \vdash t} }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash  \%\{ \overline{k: t} \} }
    \end{prooftree}
\]

Keys $\overline{k}$ also need to be pairwise distinct. \\

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t }
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t' }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash  t \vee  t' }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash  \lnot t }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{  \Sigma; \Gammatop \vdash \Gammabot }
        \hypo{ \tx \in \dom(\Gammabot) }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \tx }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo {  \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { \Sigma(\BX) = \BX : \Lambda \left( \overline{\tx : \star} \right) \{\overline D \}}
        \hypo { \overline { \Sigma; \Gammatop; \Gammabot \vdash t} }
        \infer3{  \Sigma; \Gammatop; \Gammabot \vdash \BX [\overline{\tx = t}]  }
    \end{prooftree}
\]

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot[\overline{\Next'/\Next}] \vdash M[\overline{\Next'/\Next}] : \{ \tx : \star \} \qquad \overline{\Next'} \text{ fresh } }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash M.\tx }
    \end{prooftree}
\]
where $\Gammabot[\overline{\Next'/\Next}]$ denotes simultaneous alpha-renaming.
Alpha-renaming does not affect qualified names. That is, $\Elixir.P.\tx[\ty/\tx]$ is still $\Elixir.P.\tx$.

Note that, as mentioned in the beginning of the document,
structural module signatures $\{ \overline{D} \}$ cannot appear
in source programs and in the environments.
As a result, the substitution never encounters module signatures, and
we do not need a capture-avoiding substitution.

We allow alpha-renaming here, because otherwise it would not be possible to
apply this rule if $\Gammabot$ already contains a declaration with the same name
as one of the declarations exported by $M$. An example of program that is only
wellformed if we allow alpha-renaming is given below, after the wellformedness of lists of declarations.


In the above rule, $\Sigma; \Gammatop; \Gammabot[\overline{\Next'/\Next}] \vdash M[\overline{\Next'/\Next}] : \{ \tx : \star \} $ is a typing judgement.
Thanks to the subsumption rule, $\{ \tx : \star \}$ may not be exactly the type associated with $M$ in $\Gammatop$ or $\Gammabot$,
which will typically contain more declarations.

\subsection{Singleton module type}

Let $\Gammatop(P) = X : \Moddecl[\tx] [\overline{\mathcal{D}}][\BX][\tx'][t']$.

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { \overline{\Sigma; \Gammatop; \Gammabot \vdash t} }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \langle \Elixir.P[\overline{\tx = t}] \rangle }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot }
        \hypo { X \in \dom(\Gammabot) }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \langle X \rangle }
    \end{prooftree}
\]

Note that wellformedness of the local environment implies that
$\Gammabot(X) = X : t$ and $t \preceq \mod$.

\subsection{Function on module types}

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot, \overline{N : T} \vdash  T' }
        \infer1{ \Sigma; \Gammatop; \Gammabot  \vdash (\overline{N : T}) \rightarrow T' }
    \end{prooftree}
\]

Note that $\Sigma; \Gammatop; \Gammabot, \overline{N : T} \vdash  T'$
implies that $\Gammabot, \overline{N : T}$ is wellformed, which in turn implies
that parameters $\overline{N : T}$ are wellformed and the $\overline{N}$ are pairwise distinct.

\subsection{Syntactic intersection}

By convention, the empty intersection $\bigcap \emptyset$ is equivalent to
the top type $\mathbbm{1}$, which is wellformed provided the environments are wellformed.

The syntactic intersection is associative and commutative.

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \mathbb{T} }
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash  \mathbb{T}'  }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \mathbb{T} \cap \mathbb{T}' }
    \end{prooftree}
\]

\subsection{Module signature}

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop \vdash \Gammabot }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \{ \} }
    \end{prooftree}
    \qquad
    \begin{prooftree}<
        \hypo{ \Sigma; \Gammatop; \Gammabot, D \vdash \{ \overline{D'} \} }
        \infer1[\;($ D \neq X : t$)]{ \Sigma; \Gammatop; \Gammabot \vdash \{ D, \overline{D'} \} }
    \end{prooftree}
\] \\

In the rule below we denote $\Sigma(\BX) = \BX : \Lambda (\overline{\tx : \star}). \{ \overline{D_\BX} \}$.

\[
    \begin{prooftree}
        \hypo{\overline{\Sigma; \Gammatop; \Gammabot \vdash \BX[\overline{\tx = t}]}}
        \hypo{\overline{\Sigma; \Gammatop; \Gammabot \vdash \{\overline{D}\} \preceq \{ \overline{D_\BX} \}[\overline{\tx := t}] }}
        \infer2[$\overline{\BX} \neq \emptyenv$]{ \Sigma; \Gammatop; \Gammabot \vdash  \{ \overline{D} \}_{\overline{\BX[\overline{\tx = t}]}}}
    \end{prooftree}
\] \\


$\{\overline{D_\BX} \}[\overline{\tx := t}]$ denotes simultaneous substitution of
$\overline{\tx}$ with $\overline{t}$ in each declaration in $\overline{D_\BX}$.

The substitution does not affect qualified names. That is, $\Elixir.P.\tx[\tx := t]$
is still $\Elixir.P.\tx$. \\

Note that:
\begin{itemize}
    \item $\overline{\tx} \cap \dom(\overline{D_\BX})$ must be empty (otherwise the behaviour
          $\BX : \Lambda(\overline{\tx : \star}). \{ \overline{D_\BX} \}$ would be ill-formed)
    \item $\dom(\Gammabot) \cap \dom(\overline{D_\BX})$ must be empty as well. If $\ty \in \dom(\Gammabot) \cap \dom(\overline{D_\BX})$ and $t$ uses $\ty$, then the substitution
          is unsound because $\ty$ may incorrectly refer to $(\overline{D_\BX})(\ty)$ instead of $\Gammabot(\ty)$.
          However, if this happens, the judgement
          $\Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D_\BX} \}[\overline{\tx := t}]$ will not hold because shadowing is prohibited.
          There is no need to add another guard condition.
\end{itemize}

Elixir also requires that two different implemented behaviours have disjoint domains.
We did not mention it as an explicit hypothesis in the rule above for legibility.
Furthermore, the system we propose does not require this restriction.

\paragraph{Back to alpha-renaming}

As promised above, we now give a concrete program that is only wellformed if
we allow alpha-renaming:

$$X : \{ \tx : \star,\; \texttt{default} : () \rightarrow \tx,\; \texttt{foo} : (N : \langle \Elixir.X \rangle, x : N.\tx) \rightarrow N.\tx \}$$

Admittedly, $X.\texttt{foo}$ cannot do anything interesting with the opaque
parameter $x : N.\tx$ apart from just returning it. However, we still expect the program to be wellformed.

We use $N : \langle \Elixir.X \rangle$ instead of defining a behaviour
$\BX : \{ \tx : \star \}$ only for conciseness.
This has no effect on the renaming because the local type $\tx$ and
the qualified type $X.\tx$ are considered as different types (unless they are
transparent).


When proving that this program is wellformed, we will need to prove:
$$\emptyenv; X : \{ \tx : \star,\; \texttt{default} : () \rightarrow \tx \}; \left(\tx : \star, \texttt{default} : () \rightarrow \tx \right) \vdash (N : \langle \Elixir.X \rangle, x : N.\tx) \rightarrow N.\tx$$

which will lead us to prove
$$\emptyenv; X : \{ \tx : \star,\; \texttt{default} : () \rightarrow \tx \};\left(\tx : \star,  \texttt{default} : () \rightarrow \tx, N : \langle \Elixir.X \rangle \right) \vdash N.\tx$$

then
$$\emptyenv; X : \{ \tx : \star, \; \texttt{default} : () \rightarrow \tx \}; \left(\tx : \star, \texttt{default} : () \rightarrow \tx,  N : \langle \Elixir.X \rangle \right) \vdash N : \{ \tx : \star \}$$

However, this does not hold: the type $ \{ \tx : \star \}$
is not wellformed with respect to the environments, because $\tx$ already exists in the local environment (recall shadowing is
prohibited).

Thanks to alpha-renaming, the last judgement can be replaced with
$$\emptyenv; X : \{ \tx : \star, \; \texttt{default} : () \rightarrow \tx \}; \left(\tx' : \star, \texttt{default} : () \rightarrow \tx', N : \langle \Elixir.X \rangle \right) \vdash N : \{ \tx : \star \}$$

which now holds (via $N : \langle \Elixir.X \rangle \preceq \{ \tx : \star,  \texttt{default} : () \rightarrow \tx \} \preceq \{ \tx : \star \}$).

\section{Encoding}

In this section, we extend Elixir's core type encoding to all types $t$.

We introduce Elixir's core types $\tau$:

\begin{center}
    $\tau$ ::= $k$ | $\atom$ | $\fun$ | $(\overline{\tau}) \rightarrow \tau$ | $\%\{ \overline{k : \tau} \}$ | $\tau \vee \tau$ | $\lnot \tau$ | $\mathbb{O}$ | $\alpha$ \\
\end{center}

We extend the abbrevations we defined for pretypes to core types: $\toptype$ and $\tau \wedge \tau'$.
Note that, even if they look similar, $t$ and $\tau$ are part of different type systems and should not be mixed without appropiate translation.
Elixir's semantic subtyping will be denoted $\tau \preceq \tau'$.
We denote $\tau \simeq \tau'$ when both $\tau \preceq \tau'$ and
$\tau' \preceq \tau$ hold.
 Note that this subtyping relation does not involve the
environments $\Sigma, \Gammatop$ or $\Gammabot$ at all.
We assume that the semantic subtyping of core types is already implemented and orthogonal to the module type system. \\

We assume the existence of two injective functions with non-overlapping ranges
which map local type names $\tx$ and imported types $M.\tx$ to distinguished type variables, respectively:
$\tx \mapsto \alpha_\tx$ and $M.\tx \mapsto \alpha_\tx(M)$.
We write $\alpha_\tx(M)$ instead of $\alpha_{M.\tx}$ for legibility.

Let $\mho$ be a distinguished type variable. We define $\text{eq}(\tau) = (\tau \vee \mho) \times (\lnot \tau \vee \mho)$.
$\eq(\tau)$ is always inhabited, and for all $\tau, \tau'$, $\eq(\tau) \preceq \eq(\tau')$ if and only if $\tau \simeq \tau'$.

Let $@b$, $@s$ and $@l$ be distinguished atoms.

We assume $\mho$, $@b$, $@s$ and $@l$, the $\alpha_\tx$ and the $\alpha_\tx(M)$ cannot appear in the source program. \\

Let $\Sigma, \Gammatop, \Gammabot$ be wellformed environments.

We define the translation between pretypes $t$ and core types $\tau$, denoted $\interp{t}$ (where $\Sigma; \Gammatop; \Gammabot \vdash t$), as:
\begin{center}
    \begin{tabular}{rcll}
        $ \interp{k} $                             & = & $k$                                                                                                                                                                                 \\
        $ \interp{\atom} $                         & = & $\atom$                                                                                                                                                                             \\
        $ \interp{\fun} $                          & = & $\fun$                                                                                                                                                                              \\
        $ \interp{\mathbb{O}} $                    & = & $\mathbb{O}$                                                                                                                                                                        \\
        $ \interp{\alpha} $                        & = & $\alpha$                                                                                                                                                                            \\[1.5mm]
        $ \interp{\mod} $                          & = & $\% \{ @b: \toptype \}$                                                                                                                                                     \\[1.5mm]
        $ \interp{(\overline{t}) \rightarrow t'} $ & = & $\left(\overline{\interp{t}}\right) \rightarrow \interp{t'}$                                                                                                                        \\[1.5mm]
        $ \interp{t \vee t' } $                    & = & $\interp{t} \vee \interp{t'}$                                                                                                                                                       \\[1.5mm]
        $\interp{\%\{ \overline{k : t} \}}$        & = & $\% \left\{ \overline{k : \interp{t}} \right\} \wedge \lnot \% \{ @b : \toptype \} \wedge \lnot \% \{ @s : \toptype \} \wedge \lnot \% \{ @l : \toptype \}$ \\[1.5mm]
        $ \interp{\lnot t} $                       & = & $\lnot\interp{t}$                                                                                                                                                                   \\[1.5mm]
    \end{tabular}
\end{center}

Let $P$ be such that $\Gammatop(P) = \_ : \Moddecl[\tx][\overline{D}][\BX][\tx'][t']$.
\begin{center}
    \begin{tabular}{rcll}
        $ \interp{\BX[\overline{\tx = t}]} $                     & = & \multicolumn{2}{l}{$\%\{ @b: \lnot \ulcorner\! \BX \!\urcorner, \overline{\ulcorner\!\BX.\tx\!\urcorner : \eq(\interp{t})}  \}$}                                                                                                                   \\[2mm]
        $\interp{\langle \Elixir.P[\overline{\tx = t}] \rangle}$ & = &
        \multicolumn{2}{l}{$\%\{ @s: \ulcorner\! P \!\urcorner, \overline{\ulcorner\!P.\tx\!\urcorner : \eq(\interp{t})}, @b : \toptype \} \wedge \bigwedge \overline{\interp{\BX[\overline{\tx' = t'}]}}$}                                                                                                      \\[2mm]
        $\interp{\langle X \rangle} $                            & = & $\interp{\langle M \rangle}$                                                                                                     & if $\Gammabot(X) = X : \langle M \rangle$                                                                       \\[1.5mm]
        $\interp{\langle X \rangle} $                            & = & $\% \{ @l: \lnot \ulcorner\! X \!\urcorner \} \wedge \interp{t}$                                                                 & if $\Gammabot(X) = X : t$, $t \neq \langle M \rangle$                                                           \\[3mm]
        $ \interp{\tx} $                                         & = & $\interp{t}$                                                                                                                     & if $\Gammabot(\tx) = \tx : [= t]$                                                                               \\
        $ \interp{\tx} $                                         & = & $\alpha_\tx$                                                                                                                     & if $\Gammabot(\tx) = \tx : \star$                                                                               \\
        $ \interp{\Elixir.P[\overline{\tx' = t}].\tx} $          & = & $\alpha_\tx(\Elixir.P[\overline{\tx' = \interp{t}}]) $                                                                           & if $\Elixir.P[\overline{\tx' = t}].\tx$ is opaque                                                               \\
        $ \interp{X.\tx} $                                       & = & $\interp{M.\tx} $                                                                                                                & if $X.\tx$ is opaque and $\Gammabot(X) = X : \langle M \rangle$                                                 \\
        $ \interp{X.\tx} $                                       & = & $\alpha_\tx(X)  $                                                                                                                & if $X.\tx$ is opaque and $\Gammabot(X) \neq X : \langle M \rangle$
    \end{tabular}
\end{center}

The missing case is $\interp{M.\tx}$ when $M.\tx$ is transparent.
We need to use the same trick as for the wellformedness of the type $M.\tx$
and allow alpha-renaming, which we define formally below.

Let us assume there exist fresh names $\overline{\Next'}$,
declarations $\overline{D}$ and a type $t$
such that $\Sigma; \Gammatop; \Gammabot[\overline{\Next'/\Next}] \vdash  \langle M[\overline{\Next'/\Next}] \rangle \preceq \{ \overline{D}, \tx : [= t] \}$.

$\overline{D}$ contains all the declarations necessary for the type $t$ to be wellformed,

Note that $\tx : [= t]$ does not need to be the last declaration of the module, and $\overline{D}$ does not need
to contain all the declarations of $M$ that precede $\tx$. The type $\left\{ \overline{D}, \tx : [= t] \right\}$ is
obtained via subtyping, after removing all the declarations that are not useful to typecheck $\tx$ (see corresponding section about subtyping).

We introduce meta-function $\wrap_{M, \overline{D}}(T)$, which qualifies with `$M.$` all the types declared in $\overline{D}$ appearing in $T$:

\begin{align*}
    \wrap_{M; \emptyenv}(T)                                                    & = T                                     \\
    \wrap_{M; \left(\tx \;:\; \star,\; \overline{D}\right)}(T)                 & = \wrap_{M; \overline{D}}(T[M.\tx/\tx]) \\
    \wrap_{M; \left(\tx \;:\; [= t],\;  \overline{D}\right)}(T)                & = \wrap_{M; \overline{D}}(T[M.\tx/\tx]) \\
    \wrap_{M; \left(x \;:\; \bigcap \overline{T'},\;  \overline{D}\right)}(T) & = \wrap_{M; \overline{D}}(T)            \\
\end{align*}

Note that declarations of the form $X : t$ cannot appear in module signatures.
That is why we did not define $\wrap$ on $X : t$.

Similarly, a value declaration $x' : \bigcap \overline{T'}$ is never necessary for a type
to be wellformed. If we require $\overline{D}$ to be minimal, we can also omit to define $\wrap$ on
$x : \bigcap \overline{T'}$.

We are finally able to define $\interp{M.\tx}$ formally when $M.\tx$ is transparent:

$$\interp{M.\tx} = \interp{\left(\wrap_{M[\overline{\Next'/\Next}], \overline{D}}(t)\right)[\overline{\Next/\Next'}]}$$ \\

We stress the following observations:

\begin{itemize}
    \item Modules and behaviours are invariant over their type parameters. This is enforced
          by the use of $\eq$ in the encoding.
    \item If $\tx$ is opaque, then the local $\tx$ and the qualified $\Elixir.P[\overline{\tx = \tx}].\tx$
          (where $P$ is the path of the current module) are unrelated types.
          This is intended, because hot swapping may cause the opaque type to change definition.
    \item We should also enforce that a value of type $\Elixir.P[\overline{\tx = \tx}].\tx$
          can never survive hot swapping. This is a critical soundness issue with the current encoding.
    \item When $\Gammabot(X) = X : \langle M \rangle$, then $\langle X \rangle \simeq \langle M \rangle$
          and $X.\tx \simeq M.\tx$. In other words, we treat $X$ just as a transparent alias for $M$.
          The section about typing of expressions will discuss this point further.
    \item When $\Gammabot(X) = X : t$ and $t \neq \langle M \rangle$ (for any $M$), then $\langle X \rangle$
          is a (strict) subtype of $t$. Typically, in this case, $t = \BX[\overline{\tx = t'}]$ for some behaviour $\BX$.
    \item It is trivial to know whether $\Elixir.P[\overline{\tx = t}].\tx$ is transparent or opaque.
          However, $X.\tx$ may require slightly more elaborate subtyping (see corresponding section).
\end{itemize}

\section{Subtyping}

Recall the syntactic subtyping judgement: $\Sigma; \Gammatop; \Gammabot \vdash \mathbb{T} \preceq \mathbb{T}'$.
We will denote $\Sigma; \Gammatop; \Gammabot \vdash \mathbb{T} \simeq \mathbb{T}'$ when both $\Sigma; \Gammatop; \Gammabot \vdash \mathbb{T} \preceq \mathbb{T}'$ and $\Sigma; \Gammatop; \Gammabot \vdash \mathbb{T}' \preceq \mathbb{T}$ hold.
We start with the simple case:
\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t }
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t' }
        \hypo{ \interp{t} \preceq \interp{t'} }
        \infer3{ \Sigma; \Gammatop; \Gammabot \vdash t \preceq t' }
    \end{prooftree}
\]

\subsection{Syntactic intersection}

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \bigcap_i \overline{\mathbb{T}}^i }
        \hypo{ \forall j. \exists i. \; \Sigma; \Gammatop; \Gammabot \vdash \overline{\mathbb{T}}^i \preceq \overline{\mathbb{T}'}^j }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \bigcap\limits_i \overline{\mathbb{T}}^i \preceq \bigcap\limits_j \overline{\mathbb{T}'}^j}
    \end{prooftree}
\] \\

We do not mention $\Sigma; \Gammatop; \Gammabot \vdash \bigcap \overline{\mathbb{T}'}$
as an explicit condition because $\overline{\mathbb{T}'}^j$ ranges over all $\overline{\mathbb{T}'}$.
As a result, the hypothesis $\overline{\mathbb{T}}^i \preceq \overline{\mathbb{T}'}^j$ already implies that
all the $\overline{\mathbb{T}'}^j$ are wellformed.

This rule is sound but not complete. In particular, it is much less powerful than
the semantic intersection $\wedge$ for types $t$.
In practice, this limitation can become noticeable especially when dealing with syntactic
intersections of functions with overlapping domains and complex guards.

We may explore how to make the syntactic
intersection more powerful in a future work
but, for now, we assume the practical use cases are
rare enough and we accept this limitation.

Note that with this definition, the empty intersection is a supertype of all intersections,
and therefore is a supertype of all types. This is consistent with the convention that
the empty intersection is equivalent to the top type $\toptype$.

Moreover, on types $t$, the syntactic intersection is equivalent to the semantic intersection:

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash t \wedge t'}
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash t \cap t' \preceq t \wedge t' }
    \end{prooftree}
\] \\

\subsection{Functions}

\[
    \begin{prooftree}
        \hypo { \forall i. \; \Sigma; \Gammatop; \Gammabot, \overline{N : T'}^{0..i} \vdash \overline{T'}^{i} \preceq  \overline{T}^{i} }
        \hypo{ \Sigma; \Gammatop; \Gammabot, \overline{N : T'} \vdash T_r \preceq T_r' }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{N : T}) \rightarrow T_r \preceq (\overline{N : T'}) \rightarrow T_r' }
    \end{prooftree}
\] \\

When the function signature does not use parameter names, the types
$(\overline{t}) \rightarrow t'$ and $(\overline{N : t}) \rightarrow t'$
are interchangeable:


\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{N : t }) \rightarrow t' }
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{t}) \rightarrow t'}
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{t}) \rightarrow t' \preceq (\overline{N : t }) \rightarrow t' }
    \end{prooftree}
\] \\
\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{N : t }) \rightarrow t' }
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{t}) \rightarrow t'}
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{N : t }) \rightarrow t' \preceq (\overline{t}) \rightarrow t'  }
    \end{prooftree}
\] \\

This allows to prove for instance:
\begin{align*}
    (\BX, \texttt{integer()}) \rightarrow \texttt{boolean()} & \preceq (N_1: \BX, N_2: \texttt{integer()}) \rightarrow \texttt{boolean()} \\
                                                             & \preceq (N_1 : \BX, N_2 : N_1.\tx) \rightarrow N_1.\tx'
\end{align*}

where $N_1.\tx : [= \texttt{integer()}], N_1.\tx' : [= \texttt{boolean()}]$ \\

\paragraph{Alpha-renaming} We can rename function parameters as long as the
new names are pairwise distinct and do not shadow local declarations:

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash (\overline{N : T}) \rightarrow T' }
        \hypo { \dom(\Gammabot) \cap \overline{N'} = \emptyset }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash (\overline{N' : T[\overline{N'/N}]}) \rightarrow T'[\overline{N'/N}] \preceq (\overline{N : T}) \rightarrow T' }
    \end{prooftree}
\]
where $T[\overline{N'/N}]$ denotes simultaneous renaming. \\

\subsection{Signature expansion}

In the rule below, $\Sigma; \Gammatop; \Gammabot  \vdash \{ \overline{D} \}[\overline{\tx := t}]$
implies that $\Gammabot$ does not already contain any declaration name that is also exported by $\BX$.
The same requirement applies to $\Elixir.P$ in the second rule.
As a result, applying these rules may require prior alpha-renaming as mentioned above.

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \BX[\overline{\tx = t}]}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \}[\overline{\tx := t}]}
        \infer2[\;($\Sigma(\BX) = \Lambda (\overline{\tx : \star}). \{\overline{D} \}$)]{ \Sigma; \Gammatop; \Gammabot \vdash \BX[\overline{\tx = t}] \preceq \{ \overline{D} \}[\overline{\tx := t}]}
    \end{prooftree}
\] \\

Let $\Gammatop(P) = X : \Moddecl[\tx] [\overline{\mathcal{D}}][\BX][\tx'][t']$.

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot  \vdash \langle \Elixir.P[\overline{\tx = t}] \rangle}
        \hypo { \Sigma; \Gammatop; \Gammabot  \vdash  \left(\left\{ \locals(\overline{\mathcal{D}}) \right\}_{\overline{\BX[\overline{\tx' = t'}]}}\right)[\overline{\tx := t}] }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \langle \Elixir.P[\overline{\tx = t}] \rangle \preceq \left(\left\{ \locals(\overline{\mathcal{D}}) \right\}_{\overline{\BX[\overline{\tx' = t'}]}}\right)[\overline{\tx := t}]}
    \end{prooftree}
\] \\

Note that, because of the separation between pretypes $t$ and strucural module signatures $\{ \overline{D} \}$,
signature expansion cannot traverse negation and union.

As a result, $\BX[\overline{\tx = t}] \vee \BX'[\overline{\tx' = t'}]$ is not of great use unless
$\BX = \BX'$ and $\overline{t} = \overline{t'}$.

If $X : \BX[\overline{\tx = t}] \vee \BX'[\overline{\tx' = t'}]$, then
there is no way to prove wellformedness of $X.\tx$, even if both $\BX$ and $\BX'$ declare a type $\tx$.

We accept this limitation, because in practice, the type $t$ of a function parameter $X : t$ is expected to be one of $\mod$, $\langle M \rangle$
or $\BX[\overline{\tx = t'}]$ instead of a complex combination of types.

If addressing this gap is found to be useful, it would be straightforward to add new rules such as
\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash t \preceq \mathbb{T} }
        \hypo { \Sigma; \Gammatop; \Gammabot  \vdash t' \preceq \mathbb{T} }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash t \vee t' \preceq \mathbb{T} }
    \end{prooftree}
\]

\subsection{Module weakening}

The first rule below expressed the fact that the type $\{ \overline{D} \}_{\overline{\BX[\overline{\tx = t}]}}$
essentially behaves like the syntactic intersection between
$\{ \overline{D} \}$ and the implemented behaviours.

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \}_{\overline{\BX[\overline{\tx = t}]} } }
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D'} \}_{\overline{\BX[\overline{\tx' = t'}]} } }
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \} \cap \bigcap \overline{\BX[\overline{\tx = t}]} \preceq \{ \overline{D'} \} \cap \bigcap \overline{\BX'[\overline{\tx' = t'}]}}
        \infer3{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \}_{\overline{\BX[\overline{\tx = t}]} } \preceq \{ \overline{D'} \}_{\overline{\BX'[\overline{\tx' = t'}]} } }
    \end{prooftree}
\] \\

A module signature is a subtype of all the behaviours it implements
and of the top module type $\mod$:

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \}_{\overline{\BX[\overline{\tx = t}]} }}
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \}_{\overline{\BX[\overline{\tx = t}]} } \preceq \bigcap \overline{\BX[\overline{\tx = t}]} }
    \end{prooftree}
    \qquad
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \} }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \{ \overline{D} \} \preceq  \mod }
    \end{prooftree}
\] \\

        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \{ \tx : \star, \overline{D} \} \preceq \{ \tx : \star, \overline{D'} \} }

        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \{ \tx : [= t], \overline{D} \} \preceq \{ \tx : \star, \overline{D'} \} }
    \end{prooftree}

    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot, \tx : [= t] \vdash \{\overline{D}\} \preceq \{\overline{D'}\} }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash \{ \tx : [= t], \overline{D} \} \preceq \{ \tx : [= t], \overline{D'} \} }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \bigcap \overline{T} \preceq \bigcap \overline{T'} }
        \hypo{ \Sigma; \Gammatop; \Gammabot, x : \bigcap \overline{T} \vdash \{\overline{D}\} \preceq \{\overline{D'}\} }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \{ x: \bigcap \overline{T}, \overline{D} \} \preceq \{ x: \bigcap \overline{T'}, \overline{D'} \} }
    \end{prooftree}
\] \\

The definition of transparent types cannot be altered by subtyping.
Consider for instance the function
$\texttt{foo} : (X : \{ \tx : [= \texttt{boolean()}] \}, y : X.\tx) \rightarrow X.\tx$ which
returns $\texttt{not } y$.

Because $X.\tx$ is transparent, $\interp{X.\tx} \simeq \texttt{boolean()}$ and the function is well typed.

Moreover,
$(X : \{ \tx : [= \texttt{boolean()}] \}, y : X.\tx) \rightarrow X.\tx \simeq (X : \{ \tx : [= \texttt{boolean()}] \}, y : \texttt{boolean()}) \rightarrow \texttt{boolean()}$.

If we make the definition of the transparent type covariant (respectively, contravariant),
we would be able to prove $\{ \tx : [= \texttt{boolean()}] \} \preceq \{ \tx : [= \toptype] \}$
(respectively, $\{ \tx : [= \texttt{boolean()}] \} \preceq \{ \tx : [= \texttt{true}] \}$ ).

Then, by subsumption, we would be able to prove
$\texttt{foo} : (X : \{ \tx : [= \toptype] \}, y : X.\tx) \rightarrow X.\tx$
(respectively, $\texttt{foo} : (X : \{ \tx : [= \texttt{true}] \}, y : X.\tx) \rightarrow X.\tx$),
neither of which is well-typed.

        \hypo{ \Sigma; \Gammatop \vdash \Gammabot, D_2, D_1 }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \{ D_2, D_1, \overline{D} \} \preceq \{ \overline{D'} \} }

\section{Expressions}

Recall the expression typing judgement: $\Sigma; \Gammatop; \Gammabot \vdash E : \mathbb{T}$.

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash E : \mathbb{T}}
        \hypo{ \Sigma; \Gammatop; \Gammabot \vdash \mathbb{T} \preceq \mathbb{T}' }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash E: \mathbb{T}' }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo{ \Sigma; \Gammatop \vdash \Gammabot }
        \infer1[\;($ \Gammabot(x) = x : \bigcap \overline{T}$)]{ \Sigma; \Gammatop; \Gammabot \vdash  x : \bigcap \overline{T} }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop \vdash \Gammabot  }
        \hypo { \overline{\Sigma; \Gammatop; \Gammabot \vdash E : t} }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash \%\{\overline{k = E}\} : \%\{\overline{k : t}\} }
    \end{prooftree}
\]

Keys $\overline{k}$ also need to be pairwise distinct.

\[
    \begin{prooftree}
        \hypo { \overline{ \Sigma; \Gammatop; \Gammabot, \overline{x : t} \vdash E: t'} }
        \infer1[$\overline{t'} \neq \emptyenv$]{ \Sigma; \Gammatop; \Gammabot \vdash \$ \bigwedge \overline{(\overline{t}) \rightarrow t'} \text{ fn } \overline{x} \rightarrow E : \bigwedge \overline{ (\overline{t}) \rightarrow t'} }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo { \overline{ \Sigma; \Gamma, \overline{N : T} \vdash E: T'} }
        \infer1[$\overline{T'} \neq \emptyenv$]{ \Sigma; \Gammatop; \Gammabot \vdash \$ \bigcap \overline{(\overline{N : T}) \rightarrow T'} \text{ fn } \overline{N} \rightarrow E : \bigcap \overline{(\overline{N : T }) \rightarrow T'} }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash E : \mathbb{T} }
        \hypo { \Sigma; \Gammatop; \Gammabot, N : \mathbb{T} \vdash E' : \mathbb{T}' }
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash \mathbb{T}' }
        \infer3{ \Sigma; \Gammatop; \Gammabot \vdash \text{let } N = E \text{ in } E' : \mathbb{T}' }
    \end{prooftree}
\] \\

In the rule above, the premise $\Sigma; \Gammatop; \Gammabot \vdash \mathbb{T}'$
ensures that the local variable $N$, which is only valid inside the \texttt{in} branch,
does not escape its scope and does not appear in the type $\mathbb{T}'$,
which persists outside the $\texttt{let}$ construct.


\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash E : (\overline{N' : T}) \rightarrow T'}
        \hypo { \overline{\Sigma; \Gammatop; \Gammabot \vdash N : T[\overline{N/N'}]} }
        \infer2{ \Sigma; \Gammatop; \Gammabot \vdash E(\overline{N}) : T'[\overline{N/N'}] }
    \end{prooftree}
\] \\

Since neither forward references nor variable shadowing is allowed, $\overline{N'}^i$
cannot appear in $\overline{T}^j$ for $j < i$.
This is why we wrote $\overline{T}^i[\overline{N/N'}]$ instead of $\overline{T}^i[\overline{N/N'}^{0..i}]$
in the rule above.

The hypothesis $\overline{\Sigma; \Gammatop; \Gammabot \vdash N : T[\overline{N/N'}]}$ means that
$\Sigma; \Gammatop; \Gammabot \vdash \overline{N}^i : \overline{T[\overline{N/N'}]}^i$ must hold for all $i$
without changing $\Gammabot$. It is not to be confused with the wellformedness judgement
$\Sigma; \Gammatop \vdash \Gammabot, \overline{N : T[\overline{N/N'}]}$, which would not make sense here.

We do not give a typing judgement for the application where the function has type $(\overline{t}) \rightarrow t'$
because it is a subtype of $(\overline{N : t}) \rightarrow t'$, as defined above.

\paragraph{Further discussion about the encoding of $X.\tx$} The astute reader might have noticed a seemingly severe limitation resulting from the two rules above.
Consider for instance the function: $\texttt{foo}(Y : \BX, x : Y.\tx) \rightarrow Y.\tx$.
Let us assume we want to call it with module $\Elixir.P$, which implements behaviour $\BX$,
and a local variable $\texttt{state}$ of type $\Elixir.P.\tx$. In other words, we want to type-check:
$\texttt{foo}(\Elixir.P, \texttt{state})$.

First, we need to rewrite it in normal form:
$\texttt{let } X = \Elixir.P \texttt{ in } \texttt{foo}(X, \texttt{state})$.
But then, by the rule above, the local variable $\texttt{state}$ must have type $X.\tx$ (as opposed to $\Elixir.P.\tx$),
and the return type of the application is $(Y.\tx)[X/Y] = X.\tx$, which
contains $X$ and cannot escape the $\texttt{let}$ construct!

It would be very inconvenient if the caller of function \texttt{foo} was unable
to use $\texttt{state}$ as the second argument or to expose the result of the application to its own caller.
The solution comes from the fact that we carefully encoded $\langle X \rangle$ and $X.\tx$
to be equivalent to $\langle \Elixir.P \rangle$ and $\Elixir.P.\tx$, respectively, which allows the application
to be well-typed and the result to be upcast to type $\Elixir.P.\tx$ and to escape the $\texttt{let}$ expression.

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash E : \%\{ k : t, .. \}  }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash E.k : t }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash E : \toptype }
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash E' : \mathbb{T} }
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash E'' : \mathbb{T} }
        \infer3{ \Sigma; \Gammatop; \Gammabot \vdash \left((E \in t) ? E' : E''\right) : \mathbb{T} }
    \end{prooftree}
\] \\

We may also propose a better version where we give a name to the expression being tested:
\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash E_1 : t'}
        \hypo { \Sigma; \Gammatop; \Gammabot, N : t' \wedge t \vdash E_2 : \mathbb{T}' }
        \hypo { \Sigma; \Gammatop; \Gammabot, N : t' \wedge \lnot t \vdash E_3 : \mathbb{T}'  }
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash \mathbb{T}'  }
        \infer4{ \Sigma; \Gammatop; \Gammabot \vdash \left((N = E_1 \in t) ? E_2 : E_3\right) : \mathbb{T}' }
    \end{prooftree}
\]
\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot[\overline{\Next'/\Next}] \vdash M[\overline{\Next'/\Next}] : \left\{ \overline{D}, x : \bigcap \overline{T} \right\} \qquad \overline{\Next'} fresh}
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash M.x : \bigcap \left(\overline{\wrap_{M[\overline{\Next'/\Next}]; \overline{D}}(T)}\right)[\overline{\Next/\Next'}]}
    \end{prooftree}
\]

Here again we allow alpha-renaming before signature expansion.

\[
    \begin{prooftree}
        \hypo { \Sigma; \Gammatop; \Gammabot \vdash \langle M \rangle }
        \infer1{ \Sigma; \Gammatop; \Gammabot \vdash M : \langle M \rangle }
    \end{prooftree}
\]

        \infer1{ P; \Sigma; \Gammatop; \Gammabot \vdash \left(\type \tx = t, \overline{B}\right) : \left(\tx : [= t], \overline{\mathcal{D}}\right) }
    \end{prooftree}
\] \\

    \begin{prooftree}
        \hypo{ P; \Sigma; \Gammatop\left[P \texttt{+=} \tx : \star\right]; \left(\Gammabot, \tx : [= t]\right) \vdash \overline{B} : \overline{\mathcal{D}} }

    \end{prooftree}

\section{Appendix: example of derivation tree}

Below, we prove that the following module environment is wellformed
$$A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \}, \tx' : [= \tx] \}$$

First, we prove this trivial lemma, where $\emptyenv; \emptyenv \vdash \emptyenv$
refers to the wellformedness of local environments.

\[
    \begin{prooftree}
        \infer0{  \vdash \emptyenv }
        \infer1{ \emptyenv \vdash \emptyenv }
        \infer1{ \emptyenv; \emptyenv \vdash \emptyenv }
    \end{prooftree}
\]

For conciseness and legibility we collapse $X : \Lambda (). \{ \overline{\mathcal{D}} \}$ into
$X : \{ \overline{\mathcal{D}} \}$ and

\[
    \begin{prooftree}
        \infer0{ \emptyenv; \emptyenv \vdash \emptyenv }
        \hypo{ X; \emptyenv; X : \{\}; \emptyenv \vdash \overline{\mathcal{D}} }
        \infer2{ \epsilon; \emptyenv; \emptyenv; \emptyenv \vdash X : \{ \overline{\mathcal{D}} \} }
        \infer1{ \emptyenv \vdash X : \{ \overline{\mathcal{D}} \}}
    \end{prooftree}
\]

into

\[
    \begin{prooftree}
        \hypo{ X; \emptyenv; X : \{\}; \emptyenv \vdash \overline{\mathcal{D}} }
        \infer1{ \emptyenv \vdash X : \{ \overline{\mathcal{D}} \}}
    \end{prooftree}
\]

Moreover, the proof is split in multiple subtrees so that it fits on the page.

\[
    \begin{prooftree}
        \infer0{ \emptyenv \vdash A : \{ \tx : \star \} }
        \infer1{ \emptyenv; A : \{ \tx : \star \} \vdash \emptyenv }
        \infer1{ \emptyenv; A : \{ \tx : \star \} \vdash \tx : \star }

        \infer0{ A.B; \emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash \ty : [= \Elixir.A.\tx] }

        \infer2{ A; \emptyenv; A : \{ \tx : \star \}; \tx : \star \vdash B : \{ \ty : [= \Elixir.A.\tx] \} }
        \infer1{ A; \emptyenv; A : \{ \}; \emptyenv \vdash \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \} }
        \infer1{ \emptyenv \vdash A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \} \} }
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \} \} \vdash \emptyenv }
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \} \} \vdash \tx : \star }
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \} \}; \tx : \star \vdash \tx}
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \} \} \vdash \tx : \star, \tx' : [= \tx] }
        \infer1{ A; \emptyenv; A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \} \}; \tx : \star \vdash \tx' : [= \tx] }
        \infer1{ A; \emptyenv; A : \{ \tx : \star \}; \tx : \star \vdash B : \{ \ty : [= \Elixir.A.\tx] \}, \tx' : [= \tx] }
        \infer1{ A; \emptyenv; A : \{\}; \emptyenv \vdash  \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \}, \tx' : [= \tx] }
        \infer1{ \emptyenv \vdash A : \{ \tx : \star, B : \{ \ty : [= \Elixir.A.\tx] \}, \tx' : [= \tx] \} }
    \end{prooftree}
\] \\

\[
    \begin{prooftree}
        \infer0{ \emptyenv; \emptyenv \vdash \emptyenv }
        \infer1{ \epsilon; \emptyenv; \emptyenv; \emptyenv \vdash  A : \{\} }
        \infer1{ \emptyenv \vdash  A : \{\} }
        \infer1{ \emptyenv; A : \{\} \vdash \emptyenv }
        \infer1{ \emptyenv; A : \{\} \vdash \tx : \star }
        \infer1{ A; \emptyenv; A : \{\}; \emptyenv \vdash \tx : \star }
        \infer1{ \emptyenv \vdash A : \{ \tx : \star \} }
    \end{prooftree}
\]

From now on we omit the $\Elixir.$ prefix for legibility purposes.
\[
    \begin{prooftree}

        \infer0{ \emptyenv \vdash A : \{ \tx : \star, B : \{\} \} }
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{\} \} \vdash \emptyenv}
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash \langle A \rangle }
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash A : \langle A \rangle }

        \infer0{\emptyenv \vdash A : \{ \tx : \star, B : \{\} \} }
        \infer1{\emptyenv; A : \{ \tx : \star, B : \{\} \} \vdash \emptyenv }
        \infer1{\emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash \langle A \rangle  }

        \infer0{\emptyenv \vdash A : \{ \tx : \star, B : \{\} \} }
        \infer1{\emptyenv; A : \{ \tx : \star, B : \{\} \} \vdash \emptyenv }
        \infer1{\emptyenv; A : \{ \tx : \star, B : \{\} \} \vdash \tx : \star }
        \infer1{\emptyenv; A : \{ \tx : \star, B : \{\} \}; \tx : \star \vdash \{ \}  }
        \infer1{\emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash \{ \tx : \star \}  }
        \infer2{ \emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash \langle A \rangle \preceq \{ \tx : \star \} }

        \infer2{ \emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash A : \{ \tx : \star \} }
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash A.\tx }
        \infer1{ \emptyenv; A : \{ \tx : \star, B : \{\} \} \vdash \ty : [= A.\tx] }
        \infer1{ A.B; \emptyenv; A : \{ \tx : \star, B : \{\} \}; \emptyenv \vdash \ty : [= A.\tx] }
    \end{prooftree}
\] \\

    \begin{prooftree}
        \infer0{ \emptyenv \vdash A : \{ \tx : \star \} }
        \infer1{ \emptyenv; A : \{ \tx : \star \} \vdash \emptyenv }
        \infer1{ \emptyenv; A : \{ \tx : \star \} \vdash \tx : \star }
        \infer1{ A; \emptyenv; A : \{ \tx : \star \}; \tx : \star \vdash B : \{\} }
        \infer1{ A; \emptyenv; A : \{\}; \emptyenv \vdash \tx : \star, B : \{\} }
